# Docker 部署

生产 Compose 运行一个 Node API 进程和一个内部 Nginx 容器。SQLite 使用 WAL 模式并持久化到 `./data`；容器内 Nginx 提供 Vite 静态页面，并将 `/api` 转发到 API 容器，同时关闭请求与响应缓冲以支持流式传输。

## 准备配置

```bash
cp .env.example .env
openssl rand -base64 32
```

配置稳定的 `API_KEY_MASTER_KEY`、最终 HTTPS `APP_ORIGIN`，并设置 `COOKIE_SECURE=true`。主密钥丢失或更换后，已有渠道 Key 将无法解密，用户需要重新填写。

## 启动

```bash
mkdir -p data
sudo chown -R 1000:1000 data
chmod 700 data
docker compose up -d --build
```

Web 容器只绑定 `127.0.0.1:3000`。宿主机反向代理与 TLS 可参考 `deploy/nginx-site.conf.example`，不要将 API 容器直接暴露到公网。

## 数据与备份

服务器只在 `data/ionailabs-canvas.sqlite` 保存匿名会话、加密渠道、模型分配和调用摘要，不保存画布项目、生成图片、导入媒体、音频、提示词或完整生成历史。

在线创建 SQLite 备份：

```bash
docker compose exec api npm run backup
```

恢复备份前先停止服务，同时保留数据库和完全一致的 `API_KEY_MASTER_KEY`。详细命令与出站流量边界见 `deploy/README.md`。

## 资源边界

该结构面向小型单机服务器，但模型请求和流式媒体仍会产生公网出站流量。媒体保存在浏览器只能减少服务器磁盘占用，不能消除网络出站。
