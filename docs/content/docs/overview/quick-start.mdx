# Quick Start

IonAiLabs Infinite Canvas now requires both the Vite/React frontend and the Node API. The browser never calls an AI provider directly.

## Local Docker preview

```bash
git clone git@github.com:basketikun/infinite-canvas.git
cd infinite-canvas
docker compose -f docker-compose.local.yml up --build
```

Open `http://localhost:3000`. The local Compose file uses a development-only master key and an insecure cookie, so do not use it on a public server.

## Production preparation

```bash
cp .env.example .env
openssl rand -base64 32
```

Put the generated value in `API_KEY_MASTER_KEY`, set `APP_ORIGIN` to the final HTTPS origin, and set `COOKIE_SECURE=true`. Then start the stack:

```bash
mkdir -p data
sudo chown -R 1000:1000 data
chmod 700 data
docker compose up -d --build
```

Configure host Nginx and TLS before public access. Only Nginx should expose a public port. See [Docker Deployment](/docs/overview/docker).

## First provider

Open Settings, continue past the contact prompt, then add a public HTTPS OpenAI-compatible Base URL and API Key. Refresh models from `/v1/models`, or add image and text models manually when the provider does not expose a model list.

Canvas projects and media remain in browser IndexedDB. Provider settings are scoped to the anonymous cookie and stored encrypted in server SQLite.
